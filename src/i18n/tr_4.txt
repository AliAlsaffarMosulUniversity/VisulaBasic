@@630

Why is it called "visual"?
@@633
Because you draw the program's interface with the mouse.
@@634
You drag controls onto the window, then write a short piece of code for each control.
@@635
It runs under {{Windows}}, so you need to know how a user works with {{Windows}}.
@@636
An event-driven language {{Event-Driven}}
@@637
The idea is to divide the program into small parts.
@@638
Each part runs when a particular event happens, such as:
@@639
Clicking a button with the mouse
@@640
A period of time passing
@@641
Moving the mouse pointer over a window
@@642
The golden idea: a Visual Basic program = controls on a window + small pieces of code tied to events.

@@669
Its full name is {{Integrated Development Environment}}.
@@670
It is a set of tools that gathers everything you need: designing windows, writing code, finding errors ({{Debugging}}), managing project files, editing menus and creating databases.

The {{Form Designer}} window
@@674
It has been the secret of Visual Basic's success since its first versions.
@@675
Its initial title is {{Form1}}. This is where you design the program's interface.
@@676
You place controls on it with the mouse, as if drawing boxes.
@@677
You also edit there: copy, cut, paste and move.
@@678
The {{Toolbox}}
@@679
A bar with 20 standard controls. You add them to the form by dragging or by double-clicking.
@@680
To add new controls: right-click the toolbox and choose {{Components}}. Tick the control, then {{Apply}}, then {{OK}}. For {{ActiveX}} or {{DLL}} controls use the {{Browse}} button.
@@681
To add a new tab: right-click → {{Add Tab}} → type the name → {{OK}}. To delete it: right-click the tab → {{Delete Tab}}. Warning: the controls inside it are deleted with it.
